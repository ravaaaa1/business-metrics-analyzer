## Контрольные вопросы

1. **Что такое ER-модель?** Описание сущностей, атрибутов и связей. Типы: один к одному, один ко многим, многие ко многим. Для N:M обычно нужна таблица связи.
2. **Зачем нормализация?** Она уменьшает дублирование и аномалии. 1НФ требует атомарных значений, 2НФ исключает зависимость неключевого атрибута от части ключа, 3НФ исключает транзитивные зависимости неключевых атрибутов.
3. **Чем отличается DeclarativeBase?** База SQLAlchemy 2.0 объявляется наследованием от класса DeclarativeBase. Это упрощает статическую типизацию в сравнении с динамической фабрикой declarative_base().
4. **Зачем Mapped и mapped_column?** Mapped описывает тип отображаемого атрибута, mapped_column задаёт свойства колонки, тип, PK и FK.
5. **relationship и ForeignKey?** relationship обеспечивает навигацию в ORM. ForeignKey создаёт ограничение на уровне базы данных.
6. **Зачем Alembic?** Он версионирует изменение существующей схемы, поддерживает шаги обновления и отката. create_all создаёт отсутствующие таблицы, но не ведёт историю и не меняет существующие колонки.
7. **Как сделать миграцию?** Изменить модели, выполнить `alembic revision --autogenerate -m "описание"`, проверить upgrade/downgrade, выполнить `alembic upgrade head`. Откат последней ревизии: `alembic downgrade -1`.
8. **Чем select отличается от session.query?** select строит общий объект запроса для Core и ORM. Session.execute выполняет его и возвращает Result, из которого можно извлечь строки или скаляры.
9. **Как воспроизвести Faker?** Установить seed локальному экземпляру, зафиксировать версию Faker, локаль, даты и seed для отдельного Random. Перед повтором использовать пустые таблицы.
10. **Как обеспечить целостность?** Включить FK, сначала вставить родителей, получить их PK через flush, затем вставить дочерние строки. Транзакция откатывает весь набор при ошибке.
