# ADR-004. Redis как кэш производных KPI

## Статус
Принято для целевого учебного проекта. Дата: 05.11.2026.

## Контекст
Дашборду нужен p95 ≤3 с, но кэш не должен раскрывать чужой отдел или устаревший набор.

## Решение
Ключ включает version_id, нормализованный AccessScope, период и версию формул. TTL проектно 5 минут. Перед чтением проверяется текущий доступ. При недоступности Redis считаем SQL, данные не теряются.

## Альтернативы
1. Только SQL: меньше эксплуатации, использовать как baseline.
2. Материализованные представления: быстрые агрегаты, дополнительный цикл обновления.

## Последствия
Плюсы: меньше повторных вычислений. Минусы: память и сложность ключей. Старые версии истекают по TTL. Ускорение подтверждается нагрузочным тестом, не предположением.
