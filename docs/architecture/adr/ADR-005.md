# ADR-005. Асинхронный импорт и атомарная публикация

## Статус
Принято для целевого учебного проекта. Дата: 05.11.2026.

## Контекст
До миллиона строк нельзя обрабатывать в HTTP-запросе с полной загрузкой в память. FR-03 требует отклонять ошибочный файл целиком.

## Решение
Job в PostgreSQL, отдельный worker той же кодовой базы, потоковая проверка и staging-пакеты. Одна короткая транзакция переключает активную версию и пишет аудит/outbox. Успешный hash уникален, lease позволяет повторить job после сбоя. Публикация сериализуется с проверкой expected_version.

## Альтернативы
1. Синхронный HTTP: проще, но timeout и блокировка worker API.
2. Redis/Celery: зрелая очередь, дополнительные гарантии доставки и эксплуатация, пока избыточны.

## Последствия
Плюсы: API остаётся отзывчивым, частичный набор не виден. Минусы: polling статуса, дополнительное место и уборка staging. Failed job не публикует данные. Доставка событий at-least-once, потребители идемпотентны.
