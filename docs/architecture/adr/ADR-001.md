# ADR-001. Выбор архитектурного стиля

## Статус
Принято для целевого учебного проекта. Дата: 05.11.2026.

## Контекст
Два студента, плановый MVP за две недели, существующий Python-прототип. Нужны тестируемые формулы и быстрый релиз.

## Решение
Модульный слоистый монолит с инверсией зависимостей. API и worker используют один образ. Domain содержит правила, Application порты, Infrastructure реализации.

## Альтернативы
1. Микросервисы: независимый релиз, но распределённые операции и сложность сопровождения.
2. Монолит без слоёв: быстрый старт, слабая изоляция формул.
3. Serverless: удобное автомасштабирование, дополнительные ограничения длительных импортов.

## Последствия
Плюсы: единый релиз, простая транзакция, независимые тесты ядра. Минусы: общая БД и цикл выпуска, границы модулей требуют контроля. Переход к сервисам только при измеримой необходимости.
