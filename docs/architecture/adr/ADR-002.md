# ADR-002. PostgreSQL для авторитетных данных

## Статус
Принято для целевого учебного проекта. Дата: 05.11.2026.

## Контекст
Нужны транзакции публикации набора, роли, аудит, агрегирование 100 000 сделок с ростом до миллиона.

## Решение
PostgreSQL 16, NUMERIC для денег, version_id для набора. Индексы (version_id, department, closed_date), уникальность (version_id, deal_id) и успешного hash. Job queue и outbox также в PostgreSQL.

## Альтернативы
1. SQLite: удобен для примеров, ограничивает параллельную запись API/worker.
2. Документная БД: гибкая схема, но не даёт преимуществ для табличных агрегатов и связей этого проекта.

## Последствия
Плюсы: атомарность и единая модель согласованности. Минусы: эксплуатация, миграции, резервирование, рост диска из-за staging. План запроса и индексы проверяются на реальных объёмах.
