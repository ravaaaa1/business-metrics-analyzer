# Параметры развёртывания
Это проект топологии, а не готовая конфигурация production. Приведены стартовые лимиты для оценки ресурсов, не результаты профилирования.

| Узел | Образ / ПО | CPU | RAM | Назначение |
|---|---|---:|---:|---|
| Nginx | nginx:alpine | 0,25 | 128 MiB | TLS, статика UI, reverse proxy |
| API | bma-api:<commit-sha>, FastAPI/Uvicorn | 0,5 | 512 MiB | Быстрые HTTP-сценарии |
| Worker | тот же bma-api:<commit-sha> | 0,5 | 512 MiB | Потоковый импорт, экспорт, outbox |
| PostgreSQL | postgres:16 | 0,5 | 1536 MiB | Авторитетные данные и задания |
| Redis | redis:<закреплённая версия> | 0,1 | 128 MiB | Производные KPI, eviction |
| MinIO | minio/minio:<закреплённый digest> | 0,15 | 256 MiB | Входные файлы и отчёты |

Сумма бюджетов: 2 CPU и 3072 MiB, остаётся около 1 GiB для ОС и Docker на стенде NFR-01 (2 vCPU/4 ГБ). Это тесный учебный стенд: worker имеет concurrency=1, загрузочные испытания учитывают конкуренцию. Для миллиона строк ресурсы определяются отдельным измерением. Управляемое S3 может заменить локальный MinIO без изменения приложения.

Только Nginx публикует порт 443. БД, Redis, MinIO и API не публикуют порты хоста. Между разными узлами включается TLS. Секреты JWT, пароли БД, SMTP и ключи S3 передаются Docker secrets/менеджером секретов, вне Git. Образы фиксируются digest после проверки, `latest` не используется. Миграции запускаются отдельным заданием перед переключением версии, API и worker обновляются согласованно.

Постоянные тома БД и MinIO отделены от контейнеров. Ежедневные зашифрованные резервные копии вне узла; учебные цели восстановления RPO 24 ч, RTO 4 ч требуют согласования. Проверка восстановления проводится на отдельном стенде ежемесячно. Redis не резервируется как источник истины. Статусы задач и lease позволяют повторить работу после рестарта без повторной публикации.

Health checks: /health/live проверяет процесс, /health/ready проверяет БД и совместимость схемы. Отказ кэша отражается как degraded. Метрики: p95 HTTP, ошибки, длительность/очередь импорта, возраст outbox, память worker, cache hit rate, место томов и возраст backup. Логи содержат correlation_id и не содержат JWT/паролей/содержимого реестра.
