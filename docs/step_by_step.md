# Практическое занятие № 2 — пошаговое выполнение

Ровинский Роман Олегович и Корякин Никита Иванович

Группа: Б1123-38.03.05ба(1)

Репозиторий: https://github.com/ravaaaa1/business-metrics-analyzer

## Шаг 1. Подготовить команду

Роман (@ravaaaa1) — аналитик и секретарь. Никита (@nik-auri) — заказчик и пользователь. Откройте docs/team_and_interview.md. Прочитайте границы кейса и распределение обязанностей. Четыре учебные роли совмещают два человека.

## Шаг 2. Собрать требования

По очереди разберите 18 вопросов и предложенные ответы. Проведите десятиминутную ролевую беседу. Исправьте модель ответов по итогам обсуждения. Не представляйте сгенерированный протокол как интервью с реальной компанией.

## Шаг 3. Проверить таблицы и процессы

Откройте docs/business_requirements.md: AS-IS, TO-BE, 4 BR, 11 FR, 5 NFR и 6 ограничений. Согласуйте определения KPI и права. Контрольный CSV содержит 5 сделок. Эталон: 30 000 руб.; 10 000 руб./чек; 75%; 30%.

## Шаг 4. Разобрать User Stories

В docs/user_stories.md находятся 10 историй и 23 критерия Given-When-Then. Проверьте роль, действие и ценность каждой. Затем разберите таблицу INVEST и явные зависимости. Критерии будущей мобильной версии не входят в приёмку текущего релиза.

## Шаг 5. Проверить диаграмму

Откройте docs/use_case_diagram.puml в PlantUML-совместимом редакторе. Для сдачи достаточно .puml по условиям задания. Четыре актора и UC-01–UC-10 соответствуют историям. В docs/use_cases.md разобраны импорт и отчёт, включая ошибки и отсутствие данных.

## Шаг 6. Проверить backlog

Откройте docs/product_backlog.md. MoSCoW: 3 Must, 3 Should, 3 Could, 1 Won't. Спринты по 2 недели: 13, 9 и 9 SP. Отложено 8 SP. Матрица ценности и сложности включена дополнительно. По мере реальной разработки уточняйте оценки и сроки.

## Шаг 7. Ответить на контрольные вопросы

Разберите все 7 ответов в docs/control_questions.md. На защите объясните разницу между целью бизнеса, действием программы и качеством её работы на примерах своего проекта.

## Шаг 8. Добавить одногруппника

В репозитории откройте Settings → Collaborators → Add people. Найдите строго nik-auri и отправьте приглашение. Никита должен принять его со своего аккаунта. Это отдельное действие от добавления имени в отчёт. Не удаляйте предыдущего соавтора: смена команды не требует переписывать историю проекта.

## Шаг 9. Сохранить предыдущую работу и создать ветку

Ниже резервный способ через Git, если файлы ещё не опубликованы через браузер. Если feature/add-user-stories уже создана для этой работы, продолжайте в ней вместо повторного создания. Перед изменениями убедитесь, что рабочая копия не содержит чужих незакоммиченных правок.

```powershell
git clone https://github.com/ravaaaa1/business-metrics-analyzer.git
cd business-metrics-analyzer
git status
git switch main
git pull --ff-only origin main
git switch -c feature/add-user-stories
```

Скопируйте новые файлы docs из комплекта в docs проекта. Существующий business_requirements.md сначала сравните с новой версией и сохраните полезные прежние сведения. Не заменяйте весь репозиторий архивом и не удаляйте main.py, README или историю Git. Новая документация описывает будущую веб-версию и не доказывает, что функции уже реализованы.

## Шаг 10. Коммит, push и Pull Request

```powershell
git add docs
git diff --cached --stat
git diff --cached --check
git commit -m "docs: add requirements, user stories and backlog for practice 2"
git push -u origin feature/add-user-stories
```

На GitHub откройте Pull requests → New pull request. Base: main. Compare: feature/add-user-stories. Заголовок: «ПЗ № 2: требования, User Stories и backlog». Описание: «Анализ Business Metrics Analyzer для команды Ровинский Р. О., Корякин Н. И. Добавлены учебное интервью, AS-IS/TO-BE, требования, 10 историй с 23 критериями, диаграмма, 2 сценария, backlog и ответы. Изменения касаются документации, функции приложения не реализованы». Создайте PR. Не сливайте до проверки, если преподаватель требует открытый PR.

## Шаг 11. Подготовить защиту

Используйте презентацию из 5 слайдов и docs/defense_script.md. Роман выступает по слайдам 1–3, Никита по 4–5. Репетиция занимает около 5 минут.

## Шаг 12. Сдать результат

Отправьте преподавателю ссылку на созданный PR и при необходимости презентацию. Не подставляйте ссылку на старый PR с рентабельностью. Дождитесь принятия приглашения Никитой. Реальное интервью, выступление и отправку преподавателю выполняют участники.
